# 魔靈召喚 帳號資料分析

分析《魔靈召喚（Summoners War）》帳號匯出檔（SWEX / com2us JSON 格式），產出一個**離線互動式分析工具**，涵蓋怪物盤點、符文評分、地下城隊伍建議與符文自動配裝。

- 帳號：`Lv✨九濤峰✨`（wizard_id 132789，TW 伺服器，Lv100）
- 資料日期：2026-07-10
- 環境：Windows 11 + PowerShell 5.1（本機無 Python / Node）

---

## 快速開始

1. 直接用瀏覽器開啟 **`魔靈分析工具.html`**（單一檔、離線、資料已內嵌）。
2. **要換一份新帳號資料**：點右上角 **「📥 匯入新JSON」**，直接選新的 `smw*.json`，五個分頁即時刷新，**免跑任何腳本**；旁邊 **「🗑️ 清除資料」** 可先清空目前匯入的怪物與符文（僅清畫面、不刪檔），方便換一份乾淨的新檔。
3. 想把怪物顯示成中文名 → 編輯 `對照表\怪物.csv` 的「中文」欄，再執行 `更新工具.ps1` 重建（重建後匯入的新檔也會套用中文名）。

```

   │  extract.ps1     ← 對照表(套裝/屬性代碼)、效率公式
   ▼

   │  analyze.ps1     ← monster_db.json(SWARFARM)
   ▼
units_named.json / runes_named.json          （英文命名 + 總覽統計）
   │  gen_payload.ps1 ← 對照表/怪物.csv、符文.csv （套用中文名，空則退回英文）
   ▼
p_units.json / p_runes.json                  （精簡、內嵌用）
   │  build.ps1       ← tool_template.html + app.js
   ▼
魔靈分析工具.html                              ★成品
```

> 換一份新的帳號匯出檔時，**兩種方式擇一**：
> - **最快**：直接在工具內按「📥 匯入新JSON」選新檔——`importer.js` 在瀏覽器端重跑 extract＋命名（用 build 時烤進去的 `monster_db` 與怪物中文對照），即時重繪，不需任何腳本。
> - **走管線**（要重新產出中間檔或更新對照表時）：改各腳本開頭的來源路徑，依序跑 `extract → analyze → make_maps(如需) → 更新工具.ps1`。
> 只改了對照表中文名：直接跑 `更新工具.ps1`（= gen_payload + build）。
>
> 注意：瀏覽器匯入用的是**上次 build 時內嵌的**怪物中文對照與 `monster_db`；填新中文名或更新魔靈庫後需重跑 `build.ps1` 才會反映到「匯入」功能。

## 工具功能（六分頁）

1. **魔靈庫** — 655 隻，可依屬性 / 星數 / 職業 / 天生星數 / 五圍排序篩選；名稱前顯示怪物 ICON，名稱分「中文名 / 英文名」兩欄，搜尋框中英文皆可命中。點任一列可彈出詳細視窗，顯示該魔靈 6 洞符文（洞位／套裝＋主屬＋前綴＋各條副屬，副屬點一下可把磨刀值合併／分開）；上方體質方塊可點擊切換「基礎＋符文加成」⇄「加總最終值」（加總含個人套裝加成）。
2. **怪物圖鑑** — **全部 2339 隻真魔靈**的 ICON 網格（現在遊戲裡的所有魔靈，含聯名各屬各形態、韓文名新怪；已排除水晶/王/塔/雕像/測試 dummy 等非魔靈）。可依屬性 / 職業 / 天生星數 / 覺醒狀態 / 持有狀態 篩選＋中英文搜尋。**已持有＝原色 ICON、未持有＝灰階**；標頭即時顯示「符合 N 隻／已持有 M 隻」。圖示來源 SWARFARM CDN，已下載到本機 `icons/`，離線可用。
   - 收錄範圍＝SWARFARM 有正式職業(arch≠none)的怪；其中 1977 隻常駐可召喚、362 隻為非常駐（聯名未覺醒形態、尚未在地區上架者等）。`怪物圖鑑.csv` 有「收錄」欄標示可召喚/非常駐。
   - **持有判定採「覺醒鏈等價」**：同一隻的未覺醒⇄覺醒⇄二次覺醒（及變身 transform）視為同一格，**持有其中任一形態，整條鏈都算持有並亮起原色**。（聯名怪轉原創怪為同一 `master_id`，持有即亮。）本帳號實測：精確比對 524 → 覺醒鏈等價 **1059** 隻亮起。
   - 每隻的**滿等體質(6★ Lv40)**與固定基礎值(SPD/暴率/暴傷/抵抗/命中)已放進 `對照表/怪物圖鑑.csv`（滿HP/滿ATK/滿DEF 欄）供後續設計試算用。
   - **強度 tier（S/A/B/C/D，不需匯入 JSON 就有）**：卡片左上角徽章，可依強度篩選、預設由強到弱排序。算法＝客觀分數(天生星為主)打底＋PvE meta 強怪覆蓋＋**swranking 當前版本 RTA 統計校正**(出場率≥12%、禁用率≥35% 或首選率≥6%→S…)，三者取最強。屬 swranking meta 的怪額外顯示「RTA 出場%」，可勾「只看當前版本RTA」。要手動改：編輯 `對照表/強度.csv` 的「覆蓋」欄填 S/A/B/C/D 再重建。
3. **符文庫** — 3287 個，可依套裝 / 洞位 / 主屬 / **評級** / 效率 / 已裝或倉庫 / 裝備者篩選、各欄可排序。
   - **符文評級（依網路社群評分標準）**：
     - **評級 tier**（SSS/SS/S/A/B/C）＝依效率%門檻：SSS≥110、SS≥100、S≥90、A≥80、B≥70、C<70。
     - **有效 roll**＝只計「大六」有意義副屬（速度/暴率/暴傷/攻%/血%/防%）的 roll 值（含磨刀石加成），排除固定值與抵抗/命中；數字愈高代表符文的價值愈集中在關鍵屬性。每 roll 上限(6★)：速度6、暴率6、暴傷7、攻/血/防%各8。
4. **地下城隊伍** — 內建各大地下城 meta 隊伍模板，自動標出 ✓擁有 / ✗缺少，可切「只顯示我有的」。涵蓋巨人/巨龍/死神 B12、鋼鐵要塞、懲罰者地穴、元素地下城、**次元異界龍(火/水/風)**、異界縫隙 R5、世界王。每個已擁有的隊員列尾有**「自動配裝」**按鈕：點下就地展開，以該隊建議套裝（自動辨識 4件套/2件套，不管前後順序）呼叫配裝引擎跑出該魔靈最佳符文配裝（6洞符文＋效率＋達成套裝＋配後體質，速度擺第一欄），再點一次收合。此版不做配速，只顯示配後速度供自行微調出手順序。
5. **符文自動配裝** — 選怪＋選套裝＋各洞主屬，引擎從符文池挑最佳解、湊套裝、算效率與符文加成合計；可勾選是否納入全帳號符文。**可加入複數魔靈一起配裝**：按「＋新增魔靈」增列（各自獨立設定套裝/主屬/優先屬性/門檻/含無形，可 ↑↓ 調序、✕ 移除），清單**由上到下＝優先序**——排前面的先挑最佳解，其選到的符文後面的魔靈不會再用（同一顆符文不重複套用），結果逐隻堆疊卡片呈現。**套裝需求彈性**：4件套可選「無」（不強制），2件套最多三組、可重複（例如元氣×2＝四洞元氣，套裝加成疊層）；4件套佔4洞時只開放1組2件套、選「無」則開放3組（超額洞數即時擋）；未被套裝佔用的「自由洞」不限套裝、依目標挑最佳符文。**配裝後最終體質**：以怪物體質(BASE_STATS，來源 SWARFARM 6★滿級) 套上該組符文的主/前/副屬(%＋固定值)＋套裝%加成，算出 HP/ATK/DEF/SPD/暴率/暴傷/抵抗/命中 的「基礎值 → 最終值」對照（未計入領導技/塔/神器/銘刻）。
   - **優先屬性**：可依序加入多個屬性（體力/攻擊/防禦/速度/暴率/暴傷/抵抗/命中），引擎在滿足套裝後，以各屬性最終貢獻正規化後**依序加權遞減（1、0.5、0.25…）**為目標挑符文；未加入則維持效率優先。
   - **含無形符文（補位）**：可勾選是否納入無形符文（`set_id 25`，六顆最多 1 顆）。勾選時無形可補足**缺 1 件的套裝**（例：3 顆暴走＋1 顆無形＝視同暴走 4 件套，套裝加成照算），引擎會枚舉無形擺放於哪一洞取最佳；未勾選則無形完全不參與配裝。
   - **額外門檻**：可新增任意多條「屬性 ≥ 數值」條件（以最終體質判斷）。引擎會在**不破壞選定 4/2 套裝**前提下、於同套內換副屬修補以達標；達標顯示綠字 ✓，配不出來則保留最佳嘗試並以紅字標示差距。無 BASE_STATS 基礎值的怪物會提示略過新條件。
6. **總覽** — 屬性/職業/套裝/效率分佈長條圖與關鍵指標。

> **📥 匯入新JSON**（header 右上）：隨時載入新的 `smw*.json`，全在瀏覽器端解析、即時刷新六分頁（含圖鑑持有狀態），無需重跑 PowerShell。旁邊 **🗑️ 清除資料** 先把現有匯入清空（僅清畫面、不動任何檔案）再匯入新檔更乾淨。

## 名稱對照機制

- 工具顯示名稱一律取自 `對照表\`；**中文欄有填 → 顯示中文；留空 → 自動退回英文**。
- 怪物中文：meta 相關的 152 隻已自動採 **swranking 統計頁的繁中名**（`monsterNameZho`，見 `swranking_meta.json`）；`build_catalog.py` 在 `怪物.csv` 中文為空且 swranking 有真中文時自動補上（英文名如 7R1X/Aragorn 不覆蓋你既有值）。其餘非 meta 怪仍顯示英文，可自行在 `怪物.csv`「中文」欄補；`怪物.csv` 的中文會被工具與圖鑑優先採用。
- 符文套裝/屬性/品質已預填**官方繁中**，可自行修改。
- 每隻怪同時保留 `en`（SWARFARM 英文名）供**地下城模板比對**用；顯示可換中文但比對邏輯不受影響。

### 地下城配裝 CSV（build_dungeon_fit.py）

把網路常見的各大地下城 meta 隊伍列出來，對照帳號**持有的魔靈**，再從**全帳號 6★符文**自動挑出該角色建議套裝＋主屬的最佳解，輸出到 `地下城/`。

- 隊伍與角色定位內建於腳本 `DUNGEONS`；每角的建議＝套裝提示(自動判 4/2 件套)＋依定位推的 2/4/6 洞主屬。
- 配裝引擎：每洞取符合主屬的最高效率符文，列舉哪兩洞放 2 件套(C(6,2))取最佳；**同一隊不重複用同一顆**，跨隊/跨本各自獨立（每隊視為一個可實際上陣的情境）。
- **套裝名稱依 `對照表/符文.csv` 官方繁中比對**（如 Rage=激怒、Violent=暴走、Fatal=猛攻、Focus=集中）；改了 `符文.csv` 的套裝中文，腳本內 `DUNGEONS` 的套裝字串也要同步。
- 資料來源＝最近一次 build 產出的 `work/p_runes.json`／`p_units.json`（即目前帳號）。換帳號：跑完 `extract→analyze→gen_payload` 後再執行本腳本。

### 強度 tier 與版本更新

強度 tier 內建於圖鑑（不需匯入 JSON）。三層合成、取最強：
1. **客觀分**：以天生星為主、滿等數據微調 → B/C/D 打底。
2. **PvE meta 覆蓋**：`build_catalog.py` 的 `PVE_TIER` 名單(刷本/地下城常見強怪) → S/A。
3. **swranking 版本校正**：`work/swranking_meta.json`＝swranking 當前版本 RTA 出場率/禁用率/首選率；出場率≥12%、禁用率≥35% 或首選率≥6%→S 等三 signal 取最強，反映「這版誰強」。（已以 ID 比對驗證：swranking 的屬性/圖示與本庫 159/159 全一致，底層資料無誤，故僅校正強度、不動名稱。）
4. 使用者 `對照表/強度.csv` 的「覆蓋」欄可最終覆寫任一隻。

> **版本更新後怎麼刷新 swranking 資料**：線上遊戲會不斷改動，`swranking_meta.json` 需定期更新。它抓自 `m.swranking.com` 的 `GET /api/monster/statistical?season=<季>&version=<版本>&pageSize=500&sortField=pickRate`（需該站登入 session，只能在瀏覽器內同源 fetch 取得）。回傳每隻 `monsterId(=com2us_id)`、`monsterNameZho(繁中名)`、`pickRate/winRate/banRate/firstPickRate`。更新此檔後重跑 `build_catalog.py` → `更新工具.ps1` 即套用新版本強度。
> 附帶：該 API 的 `monsterNameZho` 是官方繁中名，未來要補怪物中文名可由此取。

## 技術備註（踩過的坑）

- **PowerShell 5.1 讀 .ps1 需 UTF-8 BOM**，否則中文變亂碼；本專案腳本皆存成 BOM。
- **PS 5.1 不支援 `(if(){}else{})` 內嵌運算式**（PS7 才有），只能 `$x = if(){}else{}`。
- **已裝備符文藏在各 `unit_list[].runes` 裡**，頂層 `runes` 只有倉庫未裝的；神器同理。要合併兩邊才是完整資產。
- **符文效率公式** = (主屬ratio + Σ副屬ratio) / 2.8 × 100；`class≥11` 為上古(減10=星數)。
- **魔礦 `craft_type_id` 解碼** = set×10000 + effect×100 + grade(品質)；`craft_type` 分 1~6 種。
- 特殊套裝：`set_id 25 = Intangible(無形)`、`99 = Immemorial(遠古，僅魔礦)`，繁中名依 `對照表/符文.csv`。

# 魔靈召喚 帳號資料分析

分析《魔靈召喚（Summoners War）》帳號匯出檔（SWEX / com2us JSON 格式），產出一個**離線互動式分析工具**，涵蓋怪物盤點、符文評分、地下城隊伍建議與符文自動配裝。

- 帳號：`Lv✨九濤峰✨`（wizard_id 132789，TW 伺服器，Lv100）
- 資料日期：2026-07-10
- 環境：Windows 11 + PowerShell 5.1（本機無 Python / Node）

---

## 快速開始

> **線上版**：<https://millet0217.github.io/summonerswar-tool/>（push 到 `main` 由 GitHub Actions 自動部署，見下方「部署」）。開啟後點右上「📥 匯入新JSON」載入自己的 `smw*.json` 即可使用。

1. 直接用瀏覽器開啟 **`魔靈分析工具.html`**（單一檔、離線、資料已內嵌）。
2. **要換一份新帳號資料**：點右上角 **「📥 匯入新JSON」**，直接選新的 `smw*.json`，五個分頁即時刷新，**免跑任何腳本**；header 的玩家名稱會跟著匯入檔的 `wizard_info.wizard_name` 更新（未匯入前為空白）。旁邊 **「🗑️ 清除資料」** 可先清空目前匯入的怪物與符文（僅清畫面、不刪檔），方便換一份乾淨的新檔。
   - 符文配裝頁的 **「單/多魔靈配裝」** 與 **「套組產能分析」** 各有獨立的 **「🗑️ 清空」** 鈕，只重置該模式的清單與結果，**不會移除已匯入的 JSON**。
3. 想把怪物顯示成中文名 → 編輯 `對照表\怪物.csv` 的「中文」欄（⚠️ `更新工具.ps1` 已廢棄不可再跑，中文對照需直接改成品 HTML 內嵌的 `ZH_NAMES` 資料段）。

## 開發模式（重要）

**成品 `魔靈分析工具.html` 是唯一真相（single source of truth），所有功能直接改在成品上。**

- `work/app.js`、`work/tool_template.html`、`work/importer.js` 已 **DEPRECATED**：近期功能（符文配裝引擎 `solveFit`、套組產能分析、beam search 等）只存在成品 HTML，未同步回這些 source 檔。
- `work/build.ps1` 與 `更新工具.ps1` 已加擋板停用：執行會用過時模板覆寫成品、把配裝引擎整個回退。
- `work/` 其餘腳本（extract / analyze / gen_payload / fetch_swarfarm / build_catalog 等）仍可用於產生資料，但產出的資料要更新進成品時，需直接替換成品 HTML 內對應的單行 `const` 資料宣告（日後有需要再寫 `update_data.ps1` 專門做資料段替換）。

## 工具功能（五分頁）

1. **魔靈庫** — 655 隻，可依屬性 / 星數 / 職業 / 天生星數 / 五圍排序篩選；名稱前顯示怪物 ICON，名稱分「中文名 / 英文名」兩欄，搜尋框中英文皆可命中。點任一列可彈出詳細視窗，顯示該魔靈 6 洞符文（洞位／套裝＋主屬＋前綴＋各條副屬，副屬點一下可把磨刀值合併／分開，另有 **「磨刀：全部加總／還原」** 鈕一鍵切換這隻六顆）；上方體質方塊可點擊切換「基礎＋符文加成」⇄「加總最終值」（加總含符文副屬**磨刀值**＋體質類套裝加成：自身型 8 套＋全隊型 5 套「鬥志/決心/剛毅/命中/韌性」，單隻只算自己裝的，保護套 HP 護盾不計入）；另有「效果套裝」列，機率型套裝（絕望/暴走/反擊/封印）顯示「至少發生一次」機率，其餘只標套名。
2. **怪物圖鑑** — **2022 張魔靈卡**的 ICON 網格（現在遊戲裡的所有魔靈，含聯名各屬各形態；已排除水晶/王/塔/雕像/測試 dummy 等非魔靈，並去除同一張 icon 的重複卡與 SWARFARM 韓文名重複、廢棄舊版家族）。可依屬性 / 職業 / 天生星數 / 覺醒狀態 / 持有狀態 篩選＋中英文搜尋。**已持有＝原色 ICON、未持有＝灰階**；標頭即時顯示「符合 N 隻／已持有 M 隻」。圖示來源 SWARFARM CDN，已下載到本機 `icons/`，離線可用。
   - 收錄範圍＝SWARFARM 有正式職業(arch≠none)的怪，共 2171 隻(1977 常駐可召喚＋194 非常駐，如聯名未覺醒形態、尚未在地區上架者等)，`怪物圖鑑.csv` 有「收錄」欄標示；圖鑑顯示時再把「未覺醒與覺醒共用同一張 icon」的重複併成 1 張(留可召喚/已覺醒者)，故網格為 2022 張卡。
   - **持有判定採「覺醒鏈等價」**：同一隻的未覺醒⇄覺醒⇄二次覺醒（及變身 transform）視為同一格，**持有其中任一形態，整條鏈都算持有並亮起原色**。（聯名怪轉原創怪為同一 `master_id`，持有即亮。）本帳號實測：精確比對 524 → 覺醒鏈等價 **1059** 隻亮起。
   - 每隻的**滿等體質(6★ Lv40)**與固定基礎值(SPD/暴率/暴傷/抵抗/命中)已放進 `對照表/怪物圖鑑.csv`（滿HP/滿ATK/滿DEF 欄）供後續設計試算用。
   - **強度 tier（S/A/B/C/D，不需匯入 JSON 就有）**：卡片左上角徽章，可依強度篩選、預設由強到弱排序。算法＝客觀分數(天生星為主)打底＋PvE meta 強怪覆蓋＋**swranking 當前版本 RTA 統計校正**(出場率≥12%、禁用率≥35% 或首選率≥6%→S…)，三者取最強。屬 swranking meta 的怪額外顯示「RTA 出場%」，可勾「只看當前版本RTA」。要手動改：編輯 `對照表/強度.csv` 的「覆蓋」欄填 S/A/B/C/D 再重建。
3. **符文庫** — 3287 個，可依套裝 / 洞位 / 主屬 / **評級** / 效率 / 已裝或倉庫 / 裝備者篩選、各欄可排序。控制列有 **「磨刀：全部加總／還原」** 鈕，一鍵把目前表格所有符文的副屬磨刀值加總／還原（單列點副屬亦可個別切換）。
   - **副屬優先排序（最多 5 條，含前綴）**：可加最多 5 個副屬設優先序，每條可再填最小值。取值＝該副屬「基底＋磨刀、**含前綴**、不含主屬」；**選了某副屬＝符文必須含該副屬**（沒有就排除），填最小值則再加「≥ 門檻」硬篩。排序依 1→2→3… 逐級由大到小（字典序，前一級同分才看下一級），啟用時覆蓋欄位點擊排序，附「清除」；已在別條選過的副屬在其他下拉會**灰階不可選**避免重複。
   - **符文評級（依網路社群評分標準）**：
     - **評級 tier**（SSS/SS/S/A/B/C）＝依效率%門檻：SSS≥110、SS≥100、S≥90、A≥80、B≥70、C<70。
     - **有效 roll**＝只計「大六」有意義副屬（速度/暴率/暴傷/攻%/血%/防%）的 roll 值（含磨刀石加成），排除固定值與抵抗/命中；數字愈高代表符文的價值愈集中在關鍵屬性。每 roll 上限(6★)：速度6、暴率6、暴傷7、攻/血/防%各8。
4. **符文自動配裝** — 分頁頂端可切三個模式：**單/多魔靈配裝 ／ 套組產能分析 ／ 地下城參考隊**。選怪＋選套裝＋各洞主屬，引擎從符文池挑最佳解、湊套裝、算效率與符文加成合計；可勾選是否納入全帳號符文。配裝清單**預設空白**，由使用者自行「＋新增魔靈」加入、或從「地下城參考隊」一鍵帶入。怪物搜尋下拉框每個選項前顯示**魔靈小頭像**，仍以打名字方式過濾，方便看圖比對。**可加入複數魔靈一起配裝**：按「＋新增魔靈」增列（各自獨立設定套裝/主屬/優先屬性/門檻/含無形，可 ↑↓ 調序、✕ 移除），清單**由上到下＝優先序**——排前面的先挑最佳解，其選到的符文後面的魔靈不會再用（同一顆符文不重複套用），結果逐隻堆疊卡片呈現。**套裝需求彈性**：4件套可選「無」（不強制），2件套最多三組、可重複（例如元氣×2＝四洞元氣，套裝加成疊層）；4件套佔4洞時只開放1組2件套、選「無」則開放3組（超額洞數即時擋）；未被套裝佔用的「自由洞」不限套裝、依目標挑最佳符文。**配裝後最終體質**：以怪物體質(BASE_STATS，來源 SWARFARM 6★滿級) 套上該組符文的主/前/副屬(%＋固定值，副屬**含磨刀值**)＋套裝%加成，算出 HP/ATK/DEF/SPD/暴率/暴傷/抵抗/命中 的「基礎值 → 最終值」對照（未計入領導技/塔/神器/銘刻）。**全隊型體質套跨隊彙總**：多隻一起配裝時，全隊型套裝（鬥志ATK/決心DEF/剛毅HP/命中ACC/韌性RES）的加成會把所有魔靈已成套的份數加總後**套到每一隻身上**（全員含自己都吃），並在各卡片標示「🤝 全隊型套裝加成」。配裝結果每洞副屬亦有 **「磨刀：分開 ⇄ 加總」** 全域切換鈕（fit 分頁與地下城就地配裝各一顆，純顯示切換不重算），方便人眼識別磨刀後的實際副屬值。
   - **優先屬性**：可依序加入多個屬性（體力/攻擊/防禦/速度/暴率/暴傷/抵抗/命中），引擎在滿足套裝後，以各屬性最終貢獻正規化後**依序加權遞減（1、0.5、0.25…）**為目標挑符文；未加入則維持效率優先。
   - **含無形符文（補位）**：可勾選是否納入無形符文（`set_id 25`，六顆最多 1 顆）。勾選時無形可補足**缺 1 件的套裝**（例：3 顆暴走＋1 顆無形＝視同暴走 4 件套，套裝加成照算），引擎會枚舉無形擺放於哪一洞取最佳；未勾選則無形完全不參與配裝。
   - **額外門檻**：可新增任意多條「屬性 ≥ 數值」條件（以最終體質判斷）。引擎會在**不破壞選定 4/2 套裝**前提下、於同套內換副屬修補以達標；達標顯示綠字 ✓，配不出來則保留最佳嘗試並以紅字標示差距。無 BASE_STATS 基礎值的怪物會提示略過新條件。
   - **套組產能分析（模式切換）**：分頁頂端可切「單/多魔靈配裝 ⇄ 套組產能分析」。產能模式回答「**用整個符文池最多能同時湊出幾組達標套裝**」（例：最多能配幾組 SPD≥180 的暴走意志）。可調：4 件套＋2 件套（2 件套留空＝其餘 2 洞為自由洞）、速度門檻、**假設基礎速**、2 洞主屬（不限/速度）、只用倉庫閒置符文、含無形補位。演算法＝**貪婪最省**（各洞候選依速度升冪，用多選擇背包 DP 湊到剛好跨過門檻、不浪費快符文）＋**局部交換優化**（把各組多餘快符文換成閒置慢符文回流 leftover，再嘗試多湊一組），避免「前面把最快符文用光害總組數變少」。速度只計**符文＋自身套裝**（迅速 4 件＝+25% 速；暴走/意志不加速），未含神器與全隊型套；基礎速為假設值（同型怪基礎速相同才準）。輸出：最多組數＋各洞可用符文（瓶頸判斷）＋每組 6 洞明細與最終速度；勾無形補位時每組至多 1 顆、組卡標「無形(補位)」，組間符文絕不共用。
   - **地下城參考隊（模式切換）**：內建各大地下城 meta 隊伍模板（巨人/巨龍/死神 B12、鋼鐵要塞、懲罰者地穴、元素地下城、**次元異界龍(火/水/風)**、異界縫隙 R5、世界王）。改為**下拉選單選一個地下城**才顯示該本推薦隊，自動標出 ✓擁有 / ✗缺少、可切「只顯示我有的」。每個已擁有隊員列尾有**「自動配裝」**按鈕就地展開該魔靈最佳符文（自動辨識 4/2 件套，不管前後順序）；每隊標題旁的**「＋ 帶入配裝清單」**可把該隊已擁有角色連同建議套裝一次塞進「單/多魔靈配裝」清單並自動切回該模式一起計算。
5. **總覽** — 屬性/職業/套裝/效率分佈長條圖與關鍵指標。

> **📥 匯入新JSON**（header 右上）：隨時載入新的 `smw*.json`，全在瀏覽器端解析、即時刷新五分頁（含圖鑑持有狀態），無需重跑 PowerShell。旁邊 **🗑️ 清除資料** 先把現有匯入清空（僅清畫面、不動任何檔案）再匯入新檔更乾淨。

## 名稱對照機制

- 工具顯示名稱一律取自 `對照表\`；**中文欄有填 → 顯示中文；留空 → 自動退回英文**。
- 怪物中文：meta 相關的 152 隻已自動採 **swranking 統計頁的繁中名**（`monsterNameZho`，見 `swranking_meta.json`）；`build_catalog.py` 在 `怪物.csv` 中文為空且 swranking 有真中文時自動補上（英文名如 7R1X/Aragorn 不覆蓋你既有值）。其餘非 meta 怪仍顯示英文，可自行在 `怪物.csv`「中文」欄補；`怪物.csv` 的中文會被工具與圖鑑優先採用。
- 符文套裝/屬性/品質已預填**官方繁中**，可自行修改。
- 每隻怪同時保留 `en`（SWARFARM 英文名）供**地下城模板比對**用；顯示可換中文但比對邏輯不受影響。

### 地下城配裝 CSV（build_dungeon_fit.py）

把網路常見的各大地下城 meta 隊伍列出來，對照帳號**持有的魔靈**，再從**全帳號 6★符文**自動挑出該角色建議套裝＋主屬的最佳解，輸出到 `地下城/`。

- 隊伍與角色定位內建於腳本 `DUNGEONS`；每角的建議＝套裝提示(自動判 4/2 件套)＋依定位推的 2/4/6 洞主屬。
- 配裝引擎：每洞取符合主屬的最高效率符文，列舉哪兩洞放 2 件套(C(6,2))取最佳；**同一隊不重複用同一顆**，跨隊/跨本各自獨立（每隊視為一個可實際上陣的情境）。
- **套裝名稱依 `對照表/符文.csv` 官方繁中比對**（如 Rage=激怒、Violent=暴走、Fatal=猛攻、Focus=集中）；改了 `符文.csv` 的套裝中文，腳本內 `DUNGEONS` 的套裝字串也要同步。
- 資料來源＝最近一次 build 產出的 `work/p_runes.json`／`p_units.json`（即目前帳號）。換帳號：跑完 `extract→analyze→gen_payload` 後再執行本腳本。
- 產物：`地下城配裝_明細.csv`（每洞配哪顆、效率、現位置＝倉庫或裝在誰身上）＋`地下城配裝_總表.csv`（每角湊裝/平均效率/缺洞）。

### 強度 tier 與版本更新

強度 tier 內建於圖鑑（不需匯入 JSON）。三層合成、取最強：
1. **客觀分**：以天生星為主、滿等數據微調 → B/C/D 打底。
2. **PvE meta 覆蓋**：`build_catalog.py` 的 `PVE_TIER` 名單(刷本/地下城常見強怪) → S/A。
3. **swranking 版本校正**：`work/swranking_meta.json`＝swranking 當前版本 RTA 出場率/禁用率/首選率；出場率≥12%、禁用率≥35% 或首選率≥6%→S 等三 signal 取最強，反映「這版誰強」。（已以 ID 比對驗證：swranking 的屬性/圖示與本庫 159/159 全一致，底層資料無誤，故僅校正強度、不動名稱。）
4. 使用者 `對照表/強度.csv` 的「覆蓋」欄可最終覆寫任一隻。

> **版本更新後怎麼刷新 swranking 資料**：線上遊戲會不斷改動，`swranking_meta.json` 需定期更新。它抓自 `m.swranking.com` 的 `GET /api/monster/statistical?season=<季>&version=<版本>&pageSize=500&sortField=pickRate`（需該站登入 session，只能在瀏覽器內同源 fetch 取得）。回傳每隻 `monsterId(=com2us_id)`、`monsterNameZho(繁中名)`、`pickRate/winRate/banRate/firstPickRate`。更新此檔後重跑 `build_catalog.py`，再把產出替換進成品 HTML 的 `CATALOG` 資料段即套用新版本強度（`更新工具.ps1` 已廢棄）。
> 附帶：該 API 的 `monsterNameZho` 是官方繁中名，未來要補怪物中文名可由此取。

## 技術備註（踩過的坑）

- **PowerShell 5.1 讀 .ps1 需 UTF-8 BOM**，否則中文變亂碼；本專案腳本皆存成 BOM。
- **PS 5.1 不支援 `(if(){}else{})` 內嵌運算式**（PS7 才有），只能 `$x = if(){}else{}`。
- **已裝備符文藏在各 `unit_list[].runes` 裡**，頂層 `runes` 只有倉庫未裝的；神器同理。要合併兩邊才是完整資產。
- **符文效率公式** = (主屬ratio + Σ副屬ratio) / 2.8 × 100；`class≥11` 為上古(減10=星數)。
- **魔礦 `craft_type_id` 解碼** = set×10000 + effect×100 + grade(品質)；`craft_type` 分 1~6 種。
- 特殊套裝：`set_id 25 = Intangible(無形)`、`99 = Immemorial(遠古，僅魔礦)`，繁中名依 `對照表/符文.csv`。
